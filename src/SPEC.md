# シャッフルランチ 仕様書

> 状態：アイデア段階の下書き。「未定」と書いたところは、決まりしだい更新する。
> 画面案：https://claude.ai/artifact/NaBQC1yUqib22NfCQeRzf7 の「A案（改）：円卓＋ひとこと」を採用。

## 1. 目的

リモート勤務とオフィス勤務の社員が混ざっていて、出社日も決まっていない。そのため、新しく入った社員（中途・新卒）は一緒にランチに行く人がいなく、仕事の外で知り合いを増やす機会が少ない。

そこで「今日ランチに行きたい人」が手を挙げて、お互いを見つけられる簡単なウェブアプリを作る。

## 2. 方針

- **とにかく気軽に使えること。** 毎日の操作は「QR を読む → 空いている席をタップ」で終わるようにする。
- **アプリは「今日ランチに行きたい人」を見えるようにするだけ。** 開催・中止は決めない。行くかどうか、誰と行くかは、テーブルを見た人どうしで自由に決める。
- **誰がいるのかがわかること。** 名前だけでなく「ひとこと」を出し、新しく入った人も、どんな人がいるのかを見てから参加できるようにする。
- PC とスマホのブラウザで使う（ネイティブアプリは作らない）。QR から開くのでスマホで見やすい画面を基本にする。
- ログインはしない。社外の人は、QR の URL に入れた合言葉で防ぐ。
- 機能は最小限から始め、使われ方を見て足す。最初は通知を作らない。

## 3. 対象

- 社員全員。ただし参加できるのは **その日に出社している人** に限る。
- オフィスは1か所なので、テーブルは1つだけ。
- オンラインでのランチ（リモートの人どうし）は、今は作らない（「10. 今後の検討」を参照）。

## 4. 使い方の流れ

1. **オフィスのデスクに QR コードを置いておく。**
   QR には、合言葉付きのアプリの URL が入っている。
2. **出社した人が QR をスマホで読み取ると、今日のテーブルが開く。**
   丸いテーブルの周りに席が並び、座っている人の名前が見える。テーブルの下には、座っている人の名前とひとことの一覧がある。
3. **気になる人の席をタップすると、その人のひとことが見られる。**
4. **一緒に行きたければ、空いている席をタップして座る。**
   初回だけ名前を入力する。ひとことも書ける（書かなくてもよい）。2回目以降は名前の入力はいらない。
5. **やめたいときは、自分の席をタップして「席を立つ」。**
   ひとことの変更もここでできる。
6. **座った人は、集合時刻に集合場所へ行く。**
   集合時刻と場所は毎日同じで、テーブルの真ん中に出ている。集まった人で一緒にランチに行く。

## 5. 画面

### 5.1 今日のテーブル（アプリのトップ）

上から順に：

- 今日の日付（例：「11月2日（月）のテーブル」）
- **円卓**
  - 真ん中に集合時刻と集合場所（例：「12:00 / 1階エントランス」）。
  - 周りに席を8つ並べる。席には次の3種類がある。
    - 人が座っている席：名字の頭文字と名字を表示する。ひとことがある人には吹き出しの印を付ける。タップすると、その人のカードが開く（5.3）。
    - 自分の席：色を変えて「あなた」と表示する。タップすると、自分の席のメニューが開く（5.4）。
    - 空席：点線の丸に「＋」。タップすると座る（5.2）。
- **今日座っている人の一覧**
  - 人数と、一人ずつの名前・ひとこと（ない人は「ひとことはありません」と表示）。
  - 自分は「（あなた）」を付けて目立たせる。
- 下に案内文
  - 座る前：「空いている席（＋）をタップして座ろう」
  - 座った後：「着席中。自分の席をタップすると、ひとことの変更や席を立てます」

日付が変わると、テーブルは空に戻る。締め切りはない。

他の人が座ったり席を立ったりすると、開いている画面にすぐ反映される（再読み込みはいらない）。

### 5.2 座る（下から出てくる画面）

- 初回だけ「名前」の入力欄を出す。2回目以降は「◯◯ さんとして座ります」と表示する。
- 「ひとこと（なくてもOK）」の入力欄。例として「4月入社です／中華の気分」を薄く出す。
- 「座る」ボタン。名前が空のときは押せない。
- 「閉じる」で座らずに戻れる。

### 5.3 人のカード（下から出てくる画面）

- 名前、ひとこと（「新メンバー」の札は「9. 未定のこと」を参照）
- 「閉じる」

### 5.4 自分の席（下から出てくる画面）

- ひとことの入力欄と「ひとことを保存」ボタン
- 「席を立つ（やっぱりやめる）」ボタン
- 「閉じる」

すでに座っているときに別の空席をタップすると、その席に移る。

### 5.5 社内の人専用の画面（部外者が開いたとき）

参加者の名前などは一切出さない。

| 開き方 | 表示 |
| --- | --- |
| 合言葉なしの URL で開いた | 「このページは社内の人専用です。オフィスに置いてある QR コードを読み取って開いてください」 |
| 古い合言葉の URL で開いた | 「この QR コードは使えなくなりました。オフィスに置いてある新しい QR コードを読み取ってください」 |

## 6. 仕組み

### 6.1 合言葉と QR コード

- アプリの URL に、推測できない長い文字列（合言葉）を付ける。
  例：`https://（アプリのアドレス）/?key=k7Qm2xR9vT`
- この URL を QR コードにして印刷し、デスクに置く。使う人は合言葉を意識しない。
- 合言葉はブラウザに覚えさせる。2回目以降は、合言葉なしのアドレスやブックマークから開いても使える。
- 合言葉を知らないと、データを読むことも書くこともできないようにする。
- URL が社外に漏れたときは、合言葉を新しくして QR を刷り直す。古い合言葉は使えなくなる。
- 毎日同じ QR でよい（日付はアプリ側で判断する）。

### 6.2 名前とひとこと（ログインなし）

- ログインはしない。初回に名前を入力するだけで使える。名前はブラウザに覚えさせる。
- 裏側では Firebase の匿名認証を使い、ブラウザごとに見えない ID を持たせる。自分の席は自分しか立てない（他人の席を勝手に消せない）ようにするため。
- ブラウザごとに覚えるので、スマホと PC の両方で使う人は、それぞれで名前を入力する。機種変更したときやブラウザのデータを消したときも、入力し直しになる。
- なりすまし（他人の名前を入力すること）は防げない。社内だけで使うので、問題になりにくいと考える。
- ひとことは最大40文字。その日だけのもので、翌日は空に戻る。

## 7. 技術構成（予定）

| 役割 | 使うもの |
| --- | --- |
| 画面 | Next.js（このリポジトリ） |
| 公開 | Vercel |
| 利用者の識別 | Firebase Authentication（匿名認証） |
| データ保存 | Cloud Firestore |

### データ（ざっくり）

- `lunches/{日付}/seats/{匿名ID}`：名前、ひとこと、席の番号（0〜7）、座った時刻

1人が座れるのは1席だけ。同じ席に2人が同時に座ろうとしたときは、先に座った人を優先する。合言葉はデータの置き場所に含め、知らないと読み書きできないようにする。日付はすべて日本時間で扱う。

### すぐ反映する仕組み

Firestore のリアルタイム更新（変更を待ち受ける機能）を使い、その日のテーブルのデータが変わったら、開いているすべての画面を自動で更新する。

## 8. 受け入れ条件

次をすべて満たしたら完成とする。

### 8.1 基本の流れ

- [ ] 合言葉付きの QR を読むと、今日のテーブルが開く。
- [ ] 初めて開いた人が空席をタップすると、名前とひとことの入力画面が出る。名前を入れて「座る」を押すと、その席に自分の名前が表示される。
- [ ] 2回目以降に開いたときは、名前を入力せずに座れる。
- [ ] 人の席をタップすると、その人の名前とひとことが見られる。
- [ ] 自分の席をタップして「席を立つ」を押すと、テーブルと一覧から自分の名前が消える。
- [ ] 自分の席から、ひとことを変えられる。
- [ ] 座っている状態で別の空席をタップすると、その席に移る。
- [ ] テーブルの真ん中に、集合時刻と集合場所が表示される。
- [ ] テーブルの下の一覧の人数と、座っている席の数が一致する。

### 8.2 すぐ反映されること

- [ ] 他の人が座ると、開いている自分の画面に、再読み込みしなくても3秒以内に表示される。
- [ ] 他の人が席を立ったり、ひとことを変えたりしたときも、同じく3秒以内に反映される。
- [ ] 画面を開いたまま日付が変わると、自動で新しい日の空のテーブルに切り替わる。

### 8.3 席のルール

- [ ] 1人が座れるのは1席だけ。2つ目の席には座れない（タップすると席を移る）。
- [ ] 他の人の席を、自分が消したり動かしたりすることはできない。画面からも、データを直接書き換えようとしても、できない。
- [ ] 同じ席に2人がほぼ同時に座ろうとしたら、先の1人だけが座れる。後の人には「この席はさっき埋まりました。別の席を選んでください」と表示し、どこにも座っていない状態に戻す。

### 8.4 入力のルール

- [ ] 名前は1〜20文字。前後の空白は取り除く。空白だけの名前では座れない（「座る」ボタンが押せない）。
- [ ] ひとことは0〜40文字。41文字目以降は入力できない。前後の空白は取り除く。
- [ ] 同じ名前の人が2人いても、両方座れる（名前で人を区別しない）。
- [ ] 名前やひとことに記号や HTML のような文字列を入れても、そのまま文字として表示され、画面が崩れたり動作したりしない。

### 8.5 日付

- [ ] 日付は日本時間で判断する。日本時間の0時を過ぎると、テーブルは空になる。
- [ ] ひとことはその日だけ。翌日に座るときは、ひとことの欄は空になっている。

### 8.6 部外者を防ぐこと

- [ ] 合言葉なしの URL で初めて開くと、「このページは社内の人専用です」の画面が出る。参加者の名前・ひとこと・人数は一切表示されない。
- [ ] 古い合言葉の URL で開くと、「この QR コードは使えなくなりました」の画面が出る。参加者の情報は一切表示されない。
- [ ] 合言葉を知らない人が、データを直接読み書きしようとしても、できない（Firestore のセキュリティルールで拒否される）。
- [ ] 一度合言葉付きで開いたブラウザは、合言葉なしのアドレスやブックマークから開いても使える。合言葉を新しくしたあとは使えなくなる。

### 8.7 困ったときの表示

- [ ] 通信が切れているときは「接続できません。電波のよい場所でもう一度お試しください」と表示する。
- [ ] 座る・席を立つ・ひとことの保存に失敗したときは、失敗したことを表示し、画面は操作する前の状態に戻す（座れていないのに座ったように見せない）。
- [ ] 通信が戻ったら、再読み込みしなくても最新のテーブルが表示される。

### 8.8 対応環境

- [ ] 次のブラウザの最新版で、8.1〜8.7 がすべて動く。
  - スマホ：iPhone の Safari、Android の Chrome
  - PC：Chrome、Edge、Safari
- [ ] 画面の幅が 360px〜1440px で、表示が崩れず、横にスクロールしない。
- [ ] QR コードを iPhone と Android の標準カメラで読み取って開ける。

### 8.9 速さ

- [ ] スマホの 4G 回線で、QR を読んでからテーブルが表示されるまで3秒以内。
- [ ] 「座る」「席を立つ」を押してから、画面に反映されるまで1秒以内。

### 8.10 見やすさ・使いやすさ

- [ ] タップできるもの（席、ボタン）は、すべて縦横 44px 以上。
- [ ] 文字と背景のコントラスト比は 4.5:1 以上（大きな文字は 3:1 以上）。
- [ ] 色だけに頼らない。自分の席には「あなた」、空席には「＋」と「空席」の文字を出す。
- [ ] 読み上げ機能で、各席が「◯◯さんの席」「空席」「あなたの席」と読まれる。
- [ ] 入力欄にはすべて見出し（ラベル）が付いている。

## 10. 今後の検討

- **ログイン：** なりすましや社外への漏れが問題になったら、Google ログインを足す。
- **Slack 連携：** チャンネル `#shuffle-lunch` に、毎朝「今日ランチに行きたい人？」とアプリの URL を投稿する。
- リモートの人向けのオンラインランチ
- 人数が多い日に、少人数のグループに分ける
- 使い始めの広め方（最初の数週間、誰かが毎日座る「呼び水」など）
- 参加の記録（誰と何回行ったか）
