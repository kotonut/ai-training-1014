# シャッフルランチ 仕様書

> 状態：アイデア段階の下書き。「未定」と書いたところは、決まりしだい更新する。
> 画面案：https://claude.ai/artifact/NaBQC1yUqib22NfCQeRzf7 の「A案 After」を採用。

## 1. 目的

リモート勤務とオフィス勤務の社員が混ざっていて、出社日も決まっていない。そのため、新しく入った社員（中途・新卒）は一緒にランチに行く人がいなく、仕事の外で知り合いを増やす機会が少ない。

そこで「今日ランチに行きたい人」が手を挙げて、お互いを見つけられる簡単なウェブアプリを作る。

## 2. 方針

- **いちばん大事な操作は「今日のランチに参加する」ボタン。** 画面でいちばん目立つのはこのボタンだけにし、毎日の操作は「QR を読む → ボタンを押す」で終わるようにする。
- **アプリは「今日ランチに行きたい人」を見えるようにするだけ。** 開催・中止は決めない。行くかどうか、誰と行くかは、画面を見た人どうしで自由に決める。
- **誰がいるのかがわかること。** 名前だけでなく「ひとこと」を出し、新しく入った人も、どんな人がいるのかを見てから参加できるようにする。
- **かわいく、参加したくなる見た目にする。** 参加する人は、おにぎりのキャラクターとして丸いテーブルを囲む。ただし飾りは増やしすぎない。
- **たとえ話ではなく、そのままの言葉を使う。** 「座る」「着席」ではなく「参加する」「参加をやめる」と書く。
- PC とスマホのブラウザで使う（ネイティブアプリは作らない）。QR から開くのでスマホで見やすい画面を基本にする。
- ログインはしない。社外の人は、QR の URL に入れた合言葉で防ぐ。
- 機能は最小限から始め、使われ方を見て足す。最初は通知を作らない。

## 3. 対象

- 社員全員。ただし参加できるのは **その日に出社している人** に限る。
- オフィスは1か所なので、テーブルは1つだけ。
- オンラインでのランチ（リモートの人どうし）は、今は作らない（「10. 今後の検討」を参照）。

## 4. 使い方の流れ

1. **オフィスのデスクに QR コードを置いておく。**
   QR には、合言葉付きのアプリの URL が入っている。
2. **出社した人が QR をスマホで読み取ると、今日のランチの画面が開く。**
   丸いテーブルの周りに、参加する人がおにぎりのキャラクターとして並んでいる。下の「今日のメンバー」には、名前とひとことが並ぶ。
3. **気になる人のおにぎりをタップすると、その人のひとことが見られる。**
4. **一緒に行きたければ「今日のランチに参加する」を押す。**
   - 初回だけ、名前（とひとこと）を入れる画面が出る。
   - 2回目以降は、押すだけで参加できる。
   - 席は自動で決まる（空いている席に入る）。席を選ぶ必要はない。
5. **参加した後は、ひとことを書いたり変えたり、参加をやめたりできる。**
6. **参加した人は、集合時刻に集合場所へ行く。**
   集合時刻と場所は毎日同じで、テーブルの真ん中に出ている。集まった人で一緒にランチに行く。

## 5. 画面

### 5.1 今日のランチ（アプリのトップ）

上から順に：

**見出し**

- 日付の札：お茶碗とお箸の小さな絵と「11月2日（月）のランチ」。
- 人数に合わせて変わる一文。人数の数字は大きく、緑で目立たせる。必ず1行に収める（幅の狭い画面では、文字を小さくして収める）。

  | 状況 | 表示 |
  | --- | --- |
  | 参加する前（1人以上いる） | 今日は **3人** がランチに行きたい！ |
  | 参加した後（自分のほかにもいる） | 今日は **4人** でランチ！ |
  | 参加した後（自分だけ） | 一番乗り！ だれか来るかな？ |
  | まだ誰もいない | 一番乗りしませんか？ |

**テーブル**

- 真ん中に丸いテーブル。上から「集合」「12:00」（大きく）「1階エントランス」（白い札）を表示する。
- 周りに席を8つ並べる。
  - **参加している人：** おにぎりのキャラクター（目・ほっぺ・口があり、頭の具の色が人ごとに違う）と、その下に名字の札。タップするとその人のカードが開く（5.4）。
    - 名札は、名前を最初の空白（半角・全角）で区切った前の部分（「田中 さくら」→「田中」）。
    - 名前に空白がないときは、名前をそのまま出す。どちらの場合も4文字を超えたら、先頭4文字の後に「…」を付ける（「田中さくら」→「田中さく…」）。
  - **自分：** 緑の具のおにぎりと、緑の「あなた」の札。タップするとひとことの画面が開く（5.3）。
  - **空いている席：** お箸を添えた空のお皿。押せない。
- 8席すべて埋まった後に参加した人（9人目から）は、席なしで参加する（6.3）。テーブルの下に「ほかに◯人」の札を出す。この人たちも「今日のメンバー」には載る。

**今日のメンバー**

- 見出し「今日のメンバー」と、人数の札（例：「3人」）。
- 一人ずつ、小さなおにぎり・名前・ひとことを並べる。
  - ひとことは白い吹き出しで出す（おにぎりがしゃべっているように見せる）。
  - ひとことがない人は「ひとことはまだありません」と小さく出す。
  - 自分は名前に「（あなた）」を付ける。
- 人数が多いときは、この部分だけスクロールする。

**下のボタンの部分**（画面の下に固定）

- 参加する前：「今日のランチに参加する」ボタン（手を振る絵付き）。
- 参加した後：「参加しました！ 12:00 に 1階エントランスへ」と、「ひとことを書く」（ひとことがあれば「ひとことを変える」）と「参加をやめる」の2つのボタン。

日付が変わると、テーブルは空に戻る。締め切りはない。

他の人が参加したり、参加をやめたり、ひとことを変えたりすると、開いている画面にすぐ反映される（再読み込みはいらない）。

### 5.2 参加する（下から出てくる画面・初回だけ）

- 見出し「今日のランチに参加する」
- 「名前（次からは入力不要）」の入力欄
- 「ひとこと（なくてもOK）」の入力欄。例として「4月入社です／中華の気分」を薄く出す。
- 「参加する」ボタン。名前が空のときは押せない。
- 「閉じる」で参加せずに戻れる。

2回目以降は、この画面は出さずにすぐ参加する。

### 5.3 ひとこと（下から出てくる画面）

- 「みんなに見えます（なくてもOK）」の入力欄
- 「保存する」ボタン
- 「閉じる」

### 5.4 人のカード（下から出てくる画面）

- 名前と、ひとこと（ない人は「ひとことはありません」）
- 「閉じる」

### 5.5 社内の人専用の画面（部外者が開いたとき）

参加者の名前などは一切出さない。

| 開き方 | 表示 |
| --- | --- |
| 合言葉なしの URL で開いた | 「このページは社内の人専用です。オフィスに置いてある QR コードを読み取って開いてください」 |
| 古い合言葉の URL で開いた | 「この QR コードは使えなくなりました。オフィスに置いてある新しい QR コードを読み取ってください」 |

### 5.6 見た目

- **色：** 緑系でまとめる。背景は薄いミント、参加ボタンは深緑。画面でいちばん濃い色は参加ボタンだけにする。テーブルはボタンより明るい緑。おにぎりの具（梅のやわらかい赤、鮭の淡いオレンジ、卵の黄色、自分は落ち着いた緑）は、くすませて強さをそろえる。
- **文字：** 書体を2つに分ける。
  - 見出しの一文、「集合 / 12:00」、「今日のメンバー」、参加ボタン、参加後の「参加しました！」、下から出てくる画面の見出し：Kiwi Maru（太さ 500）。やわらかい丸みで、画面の顔になる部分だけに使う。
  - 名前、ひとこと、札、説明、入力欄など：Zen Kaku Gothic New。読みやすさを優先する。
  - 太字（700）は名前や入力欄の見出しなど必要なところだけにし、全部を太字にしない。
- **余白：** テーブルと「今日のメンバー」の間はしっかり空け、詰め込まない。

### 5.7 動き（アニメーション）

| いつ | 動き |
| --- | --- |
| 画面を開いたとき | おにぎりが1つずつ「ぽんっ」と跳ねて現れる。その後、ゆらゆら小さく揺れ続ける |
| 参加する前 | 参加ボタンがときどき小さく弾み、手の絵が手を振る |
| 参加したとき | 自分のおにぎりが空いた席に跳ねて入り、紙吹雪が弾ける |
| 一覧・下から出てくる画面 | 下からふわっと出る |

端末で「動きを減らす」設定をしている人には、動きをすべて止める。

## 6. 仕組み

### 6.1 合言葉と QR コード

- アプリの URL に、推測できない長い文字列（合言葉）を付ける。
  例：`https://（アプリのアドレス）/?key=k7Qm2xR9vT`
- この URL を QR コードにして印刷し、デスクに置く。使う人は合言葉を意識しない。
- 合言葉はブラウザに覚えさせる。2回目以降は、合言葉なしのアドレスやブックマークから開いても使える。
- 合言葉を知らないと、データを読むことも書くこともできないようにする。
- URL が社外に漏れたときは、合言葉を新しくして QR を刷り直す。古い合言葉は使えなくなる。古い合言葉は一覧として残しておき、「古い QR で開いた」ことを見分けるのに使う。
- 開いたときの判定：

  | 合言葉 | 開く画面 |
  | --- | --- |
  | URL に今の合言葉がある | 今日のランチ（その合言葉をブラウザに覚えさせる） |
  | URL にはないが、ブラウザが今の合言葉を覚えている | 今日のランチ |
  | URL、またはブラウザが覚えている合言葉が古い合言葉 | この QR コードは使えなくなりました |
  | 合言葉がどこにもない | このページは社内の人専用です |
  | URL の合言葉が、今のものでも古いものでもない（でたらめ） | このページは社内の人専用です（当たり外れのヒントを出さない） |

  URL とブラウザの両方に合言葉があるときは、URL を優先する。
- 毎日同じ QR でよい（日付はアプリ側で判断する）。

### 6.2 名前とひとこと（ログインなし）

- ログインはしない。初回に名前を入力するだけで使える。名前はブラウザに覚えさせる。
- 裏側では Firebase の匿名認証を使い、ブラウザごとに見えない ID を持たせる。自分の参加は自分しか取り消せない（他人の参加を勝手に消せない）ようにするため。
- ブラウザごとに覚えるので、スマホと PC の両方で使う人は、それぞれで名前を入力する。機種変更したときやブラウザのデータを消したときも、入力し直しになる。
- なりすまし（他人の名前を入力すること）は防げない。社内だけで使うので、問題になりにくいと考える。
- ひとことは最大40文字。その日だけのもので、翌日は空に戻る。
- 入力のルール（名前とひとこと共通）：
  - 文字数は、見た目の1文字を1文字として数える（「👋🏽」も「あ」も「A」も1文字）。
  - 前後の空白（半角スペース、全角スペース、改行、タブ）を取り除いてから、文字数を数える。
  - 途中の改行は、空白1つに置き換える（貼り付けたときなど）。

### 6.3 席の決め方

- 参加すると、空いている席のうち番号のいちばん小さい席（0〜7）に自動で入る。
- 8席すべて埋まっているときは、席なしで参加する（席の番号は「なし」）。テーブルには出ないが、「今日のメンバー」には載る。席が空いても、後から席に移ることはしない。
- 席の場所に意味はない（実際の座席ではなく、テーブルの絵の中の位置）。
- 2人がほぼ同時に参加しても、同じ席に重ならないようにする（席の割り当てはデータベースのトランザクションで行う）。

## 7. 技術構成（予定）

| 役割 | 使うもの |
| --- | --- |
| 画面 | Next.js（このリポジトリ） |
| 公開 | Vercel |
| 利用者の識別 | Firebase Authentication（匿名認証） |
| データ保存 | Cloud Firestore |

### データ（ざっくり）

- `lunches/{日付}/members/{匿名ID}`：名前、ひとこと、席の番号（0〜7、席なしのときは「なし」）、おにぎりの具の色、参加した時刻

1人が参加できるのは1回（1席）だけ。合言葉はデータの置き場所に含め、知らないと読み書きできないようにする。日付はすべて日本時間で扱う。

### すぐ反映する仕組み

Firestore のリアルタイム更新（変更を待ち受ける機能）を使い、その日のデータが変わったら、開いているすべての画面を自動で更新する。

## 8. 受け入れ条件

次をすべて満たしたら完成とする。

### 8.1 基本の流れ

- [ ] 合言葉付きの QR を読むと、今日のランチの画面が開く。
- [ ] 初めて開いた人が「今日のランチに参加する」を押すと、名前とひとことの入力画面が出る。名前を入れて「参加する」を押すと、テーブルに自分のおにぎりが、「今日のメンバー」に自分の名前が出る。
- [ ] 2回目以降は、「今日のランチに参加する」を押すだけで、入力画面なしで参加できる。
- [ ] 参加すると、空いている席のうち番号のいちばん小さい席に自動で入る。席を選ぶ操作はない。
- [ ] 8席すべて埋まっているときに参加すると、席なしで参加できる。テーブルの下に「ほかに◯人」が出て、「今日のメンバー」に載る。
- [ ] 人のおにぎりをタップすると、その人の名前とひとことが見られる。
- [ ] 参加した後、「ひとことを書く／変える」でひとことを保存できる。自分のおにぎりをタップしても同じ画面が開く。
- [ ] 「参加をやめる」を押すと、テーブルと「今日のメンバー」から自分が消え、下は「今日のランチに参加する」ボタンに戻る。
- [ ] 空いている席（お皿）は押しても何も起きない。
- [ ] テーブルの真ん中に「集合」「12:00」「1階エントランス」が表示される。
- [ ] 見出しの一文が、5.1 の表のとおり人数と状況に合わせて変わる。
- [ ] 見出しの一文は、画面の幅が 360px でも折り返さず1行に収まり、はみ出さない。
- [ ] 見出しの人数と「今日のメンバー」の人数が一致する。また、テーブルのおにぎりの数と「ほかに◯人」の数を足すと、その人数になる。
- [ ] おにぎりの名札が、5.1 のルールどおりに出る（名字だけ／空白がなければそのまま／4文字を超えたら「…」）。

### 8.2 すぐ反映されること

- [ ] 他の人が参加すると、開いている自分の画面に、再読み込みしなくても3秒以内に表示される。
- [ ] 他の人が参加をやめたり、ひとことを変えたりしたときも、同じく3秒以内に反映される。
- [ ] 画面を開いたまま日付が変わると、自動で新しい日の空のテーブルに切り替わる。

### 8.3 参加と席のルール

- [ ] 1人が参加できるのは1回だけ。参加中は「今日のランチに参加する」ボタンは出ない。
- [ ] 2人がほぼ同時に参加しても、2人とも参加でき、同じ席に重ならない。
- [ ] 他の人の参加を、自分が取り消したり書き換えたりすることはできない。画面からも、データを直接書き換えようとしても、できない。

### 8.4 入力のルール

- [ ] 名前は1〜20文字。前後の空白は取り除く。空白だけの名前では参加できない（「参加する」ボタンが押せない）。
- [ ] ひとことは0〜40文字。41文字目以降は入力できない。前後の空白は取り除く。
- [ ] 文字数は見た目の1文字を1文字として数える（「👋🏽」は1文字）。
- [ ] 取り除く空白には、全角スペース・改行・タブも含む。全角スペースだけの名前では参加できない。
- [ ] ひとことの途中の改行は、空白1つに置き換わる。
- [ ] 同じ名前の人が2人いても、両方参加できる（名前で人を区別しない）。
- [ ] 名前やひとことに記号や HTML のような文字列を入れても、そのまま文字として表示され、画面が崩れたり動作したりしない。

### 8.5 日付

- [ ] 日付は日本時間で判断する。日本時間の0時を過ぎると、テーブルは空になる。
- [ ] ひとことはその日だけ。翌日に参加するときは、ひとことは空になっている。

### 8.6 部外者を防ぐこと

- [ ] 合言葉なしの URL で初めて開くと、「このページは社内の人専用です」の画面が出る。参加者の名前・ひとこと・人数は一切表示されない。
- [ ] 古い合言葉の URL で開くと、「この QR コードは使えなくなりました」の画面が出る。参加者の情報は一切表示されない。
- [ ] でたらめな合言葉の URL で開くと、「このページは社内の人専用です」の画面が出る。
- [ ] URL とブラウザの両方に合言葉があるときは、URL の合言葉で判定する。
- [ ] 合言葉を知らない人が、データを直接読み書きしようとしても、できない（Firestore のセキュリティルールで拒否される）。
- [ ] 一度合言葉付きで開いたブラウザは、合言葉なしのアドレスやブックマークから開いても使える。合言葉を新しくしたあとは使えなくなる。

### 8.7 困ったときの表示

- [ ] 通信が切れているときは「接続できません。電波のよい場所でもう一度お試しください」と表示する。
- [ ] 参加する・参加をやめる・ひとことの保存に失敗したときは、失敗したことを表示し、画面は操作する前の状態に戻す（参加できていないのに参加したように見せない）。
- [ ] 通信が戻ったら、再読み込みしなくても最新の状態が表示される。

### 8.8 見た目と動き

- [ ] 画面でいちばん濃い色は「今日のランチに参加する」ボタンだけ。テーブルや見出しがボタンより目立たない。
- [ ] 5.7 の表の動きがすべて入っている。
- [ ] 端末で「動きを減らす」設定にすると、動きがすべて止まる（表示や操作はそのまま使える）。
- [ ] 人数が多くても、「参加する」ボタンは画面の下に見えたまま（「今日のメンバー」だけがスクロールする）。

### 8.9 対応環境

- [ ] 次のブラウザの最新版で、8.1〜8.8 がすべて動く。
  - スマホ：iPhone の Safari、Android の Chrome
  - PC：Chrome、Edge、Safari
- [ ] 画面の幅が 360px〜1440px で、表示が崩れず、横にスクロールしない。
- [ ] QR コードを iPhone と Android の標準カメラで読み取って開ける。

### 8.10 速さ

- [ ] スマホの 4G 回線で、QR を読んでから画面が表示されるまで3秒以内。
- [ ] 「参加する」「参加をやめる」を押してから、画面に反映されるまで1秒以内。

### 8.11 見やすさ・使いやすさ

- [ ] タップできるもの（おにぎり、ボタン）は、すべて縦横 44px 以上。
- [ ] 文字と背景のコントラスト比は 4.5:1 以上（大きな文字は 3:1 以上）。
- [ ] 色だけに頼らない。自分のおにぎりには「あなた」の札、ほかの人には名字の札を出す。
- [ ] 読み上げ機能で、おにぎりが「◯◯さん。タップしてひとことを見る」「あなた。タップしてひとことを書く」と読まれる。空いている席（お皿）は読み上げない。
- [ ] 入力欄にはすべて見出し（ラベル）が付いている。

## 9. 未定のこと

## 10. 今後の検討

- **ログイン：** なりすましや社外への漏れが問題になったら、Google ログインを足す。
- **Slack 連携：** チャンネル `#shuffle-lunch` に、毎朝「今日ランチに行きたい人？」とアプリの URL を投稿する。
- **「新メンバー」の札：** 今はひとことに任せる（例：「4月入社です」）。必要になったら、本人がチェックを入れて付ける形を考える。
- リモートの人向けのオンラインランチ
- 人数が多い日に、少人数のグループに分ける
- 使い始めの広め方（最初の数週間、誰かが毎日参加する「呼び水」など）
- 参加の記録（誰と何回行ったか）
